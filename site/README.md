# Design Bridge Site

English | [简体中文](./README-zh_CN.md)

Bilingual documentation and API reference for Design Bridge.

## Install

Use Node.js 24+, pnpm 10+, and GNU Make. Run all commands from the repository root:

```bash
pnpm install
```

## Site data

- `data/api/`: API manifest and localized TypeDoc snapshots. These are inputs to the other data-generation steps.
- `manual-source/`: tracked `navigation.json` and bilingual Markdown source files.
- `data/manual/`, `data/package-readmes/`, `data/search/`: generated by `make site-data`.
- `docs.config.json`: API, manual, and localized site-page metadata for document generation and the site runtime.
- `packages/*/README*.md`: package README sources mapped by `site/docs.config.json`.

`make site-data` runs `manual-sync`, builds package README data, and updates search indexes. Use `make manual-sync`
directly only when refreshing manuals alone. API snapshots must already be present in `site/data/api/`; download them
from the CDN or generate current snapshots with `make api-docs`.


## Configuration flow

`docs.config.json` declares document sources, supported locales, page metadata, and the production data prefix. `site.config.ts` exports complete, typed `DocsSiteOptions`: it selects development/production data URLs, resolves brand URLs, merges messages, and assembles API options. `src/app.tsx` only binds the declared pages to React renderers and mounts `<DocsSite config={siteConfig} pages={pages} />`.

`docs.config.json` defines `homeHref` as `/`. The runtime uses it for Home and brand links, including the app's not-found page; route paths use the configured site base.

`docs.config.json` declares only `dataBaseUrls.production`; development uses local data. Both environment entries are optional. Omitting production uses data published under the site's base path, which must be included in the deployed artifact or served there by the host. The configuration module selects the environment prefix directly, with the app base as its fallback.

The app binds each page declaration to its renderer. Every declared page must have a renderer; `home` binds the null-slug homepage. `sourceLocale` is the document source language (`en`), while `defaultLocale` is the browsing fallback (`zh-CN`). The route base and published data prefix are independent; the latter is the prefix before `data/`.

## Local development

Prepare API snapshots if needed, then run:

```bash
make site-data
pnpm dev:site
```

Local preview does not require a CDN upload. The site runs at `http://localhost:8081`; the workbench uses `pnpm dev`
at `http://localhost:8080`.

## Deployment

Generate document data locally and publish `site/data/` to the configured CDN:

```bash
make site-data
```

The deployment workflow builds the single-page app. Ordinary CI runs code checks and tests without building the site.
To build the deployable site locally:

```bash
SITE_BASE_PATH=/design-bridge/ make build-site
```

Deploy `site/dist/` and publish `site/data/` separately. `make build-site` runs Vite with `site/index.html` and
`site/404.html` as HTML entries. Both load the same app, and Vite builds their asset references.
It needs no local document data or route list. `DocsSite` uses browser routing, so GitHub Pages'
custom 404 response loads the app for direct links and refreshes. The initial response for these paths remains HTTP 404.
Set `VITE_SITE_ORIGIN` when the runtime needs an explicit origin.

## API documentation translation

`make api-docs` generates TypeDoc snapshots from source; it does not translate them. To translate an existing snapshot,
use the `api-documentation-translation` skill:

1. Select the package, version, and target-locale wrapper listed in `site/data/api/manifest.json`.
2. Run `pnpm exec galacean-docs api extract --config site/docs.config.json <snapshot-path>` to create a
   translation task.
3. Use the skill to translate task comments into the matching translation JSON, preserving task keys, code tokens,
   and other JSON data.
4. Run `pnpm exec galacean-docs api apply --config site/docs.config.json <task-path> <translation-path>`, then
   run `make site-data` to refresh search data.

Use the wrapper path from the manifest, not a content-addressed file under `api/snapshots/`. Do not edit snapshots
directly. Translation tasks are stored under the ignored `tmp/docs-tools/api-translation/` directory.
