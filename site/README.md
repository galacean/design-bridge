# Design Bridge Site

English | [简体中文](./README-zh_CN.md)

Bilingual documentation and API reference for Design Bridge.

## Install

Use Node.js 24+, pnpm 10+, and GNU Make. Run all commands from the repository root:

```bash
pnpm install
```

## Site data

- `data/api/`: API manifest and localized TypeDoc snapshots, prepared by the `api-docs` step of `make site-data`.
- `manual-source/`: tracked `navigation.json` and bilingual Markdown source files.
- `data/manual/`, `data/package-readmes/`, `data/search/`: generated by `make site-data`.
- `docs.config.json`: API, manual, and localized site-page metadata for generation and static routes.
- `packages/*/README*.md`: package README sources mapped by `site/docs.config.json`.

`make site-data` runs `manual-sync`, `api-docs`, `package-readmes`, and `search-index` in that order. Each target can
also run separately. API generation reuses complete configured versions and generates missing snapshots; restore
existing API data and translation archives first when preserving published history or translations.

## Configuration flow

`docs.config.json` declares document sources, supported locales, page metadata, and the production data prefix. `site.config.ts` exports complete, typed `DocsSiteOptions`: it selects development/production data URLs, resolves brand URLs, merges messages, and assembles API options. `src/app.tsx` only binds the declared pages to React renderers and mounts `<DocsSite config={siteConfig} pages={pages} />`.

`docs.config.json` defines `homeHref` as `/`. The runtime and static 404 page share it for all Home and brand links; route paths use the configured site base.

`docs.config.json` declares only `dataBaseUrls.production`; development uses local data. Both environment entries are optional. Omitting production uses data published under the site's base path, which must be included in the deployed artifact or served there by the host. The configuration module selects the environment prefix directly, with the app base as its fallback.

The CLI checks static route declarations; the app binds each declaration to its renderer. Every declared page must have a renderer; `home` binds the null-slug homepage. `sourceLocale` is the document source language (`en`), while `defaultLocale` is the browsing fallback (`zh-CN`). The route base and published data prefix are independent; the latter is the prefix before `data/`.

## Local development

Generate site data, then start the preview:

```bash
make site-data
pnpm dev:site
```

Local preview does not require a CDN upload. The site runs at `http://localhost:8081`; the workbench uses `pnpm dev`
at `http://localhost:8080`. Rerun `make site-data` after changing manual sources or package READMEs. After applying
API translations, `make search-index` refreshes search data without rerunning the other generation steps.

## Deployment

```bash
SITE_BASE_PATH=/design-bridge/ make build-site
```

`make build-site` runs `site-data`, builds the frontend with Vite, and generates static routes from the prepared data.
Publish the resulting `site/data/` to the CDN and deploy `site/dist/` to the site host. Set `VITE_SITE_ORIGIN` when
canonical links need an explicit origin.

## API documentation translation

`make api-docs` invokes API generation for the latest version configured in `docs.config.json`. Complete snapshots
are reused. To rebuild an existing version after API source or comment changes, run
`pnpm exec galacean-docs api generate --config site/docs.config.json --force`.
Generation does not translate comments. To translate an existing snapshot, use the
`api-documentation-translation` skill:

1. Select the package, version, and target-locale wrapper listed in `site/data/api/manifest.json`.
2. Run `pnpm exec galacean-docs api extract --config site/docs.config.json <snapshot-path>` to create a
   translation task.
3. Use the skill to translate task comments into the matching translation JSON, preserving task keys, code tokens,
   and other JSON data.
4. Run `pnpm exec galacean-docs api apply --config site/docs.config.json <task-path> <translation-path>`, then
   run `make search-index` to refresh search data.

Use the wrapper path from the manifest, not a content-addressed file under `api/snapshots/`. Do not edit snapshots
directly. Translation tasks are stored under the ignored `tmp/docs-tools/api-translation/` directory.
